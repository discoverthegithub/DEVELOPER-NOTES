01 — Foundations

Server Setup

Express.js se server banana — app.js vs server.js ka role, aur response bhejne ka tarika.

🏗️ app.js vs server.js — dono ka kaam alag hai

Yeh ek important separation hai jo beginners miss karte hain:

📄 app.js
Express app create hota hai yahan. Middleware aur routes define hote hain. Export hota hai server.js ke liye.
🚀 server.js
Sirf server start karta hai. DB connect karta hai. Port pe listen karta hai.
server.js
// server.js — sirf server start karta hai
const app = require('./src/app');
const connectDB = require('./src/db/db');
require('dotenv').config();

const PORT = process.env.PORT || 5000;

connectDB();               // Step 1: database connect karo
app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
src/app.js
// app.js — Express app create hota hai yahan
const express = require('express');
const app = express();

app.use(express.json());        // middleware
app.use('/api/users', userRoutes);   // routes register

module.exports = app;          // export kar do server.js ke liye
Response kaise bhejte hain?
Frontend ko data dena ho to res.json() use karo — yeh JSON format mein data bhejta hai. Sirf text dena ho to res.send().

03 — Database

MongoDB Atlas Connection

MongoDB Atlas pe cluster banao, phir apni app ko connect karo. Local address ki jagah zeros use karte hain.

1
MongoDB Atlas pe cluster banao
mongodb.com/atlas pe jao, free cluster create karo. Apna region choose karo.
2
IP Address whitelist karo — 0.0.0.0/0
Local machine ka IP likhne ki bajay 0.0.0.0/0 likhte hain — iska matlab "koi bhi IP se connect ho sakta hai". WiFi change hone pe bhi connection nahi tootega.
3
Connection string .env mein save karo
Username, password aur database name replace karo apni connection string mein.
4
db.js mein connection logic likho
Alag db.js file banao, wahan connection karo, export karo, server.js mein import karo.
src/db/db.js
const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGO_URI);
    console.log(`✅ MongoDB Connected: ${conn.connection.host}`);
  } catch (error) {
    console.error(`❌ Error: ${error.message}`);
    process.exit(1);  // DB fail ho to server band karo
  }
};

module.exports = connectDB;
Folder structure tip: src/db/db.js — src ke andar db folder banao, usme db.js file. Yeh clean separation hai.

05 — Models

Models & Schema

Database mein data store karne se pehle bataana padta hai ke data kaisa dikhega — yeh kaam schema karta hai.

Schema kya hota hai? ▼

Schema ek blueprint hai — jaise koi form hai jis mein kya fields honge, kya required hai, kya type hoga. Mongoose mein hum yeh define karte hain.

String Number Boolean Date ObjectId (reference) required: true unique: true default: value
src/models/User.model.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: [true, 'Name is required'],
  },
  email: {
    type: String,
    required: true,
    unique: true,     // sirf unique email se register ho sakta hai
    lowercase: true,
  },
  role: {
    type: String,
    enum: ['patient', 'doctor'],  // sirf yeh 2 values allowed
    default: 'patient',
  },
}, { timestamps: true });  // createdAt, updatedAt auto add

module.exports = mongoose.model('User', userSchema);
unique: true ka matlab? Agar koi already us email se register hai, to naya registration reject ho jaega. MongoDB level pe enforcement hoti hai.
06 — Routes

Routes

Routes sirf URL endpoints define karte hain — logic nahi. Logic controller mein hoti hai.

Routes ka rule — sirf route banao, logic mat likho

Routes file mein sirf yeh hona chahiye: HTTP method + URL path + controller function. Kuch nahi.

src/routes/user.routes.js
const express = require('express');
const router  = express.Router();
const { register, login, getUser } = require('../controllers/auth.controller');
const { protect } = require('../middleware/auth.middleware');

// Public routes — koi bhi access kar sakta
router.post('/register', register);
router.post('/login',    login);

// Protected route — sirf logged-in user
router.get('/:id', protect, getUser);  // :id — dynamic parameter

module.exports = router;

07 — Controllers

Controllers

Saari business logic yahan hoti hai — database se data lana, process karna, response dena.

src/controllers/auth.controller.js
const User = require('../models/User.model');

// Register controller
const register = async (req, res) => {
  try {
    // body mein data aaya frontend se — express.json() ne parse kiya
    const { name, email, password } = req.body;

    // Check: email already exist karta hai?
    const existing = await User.findOne({ email });
    if (existing) {
      return res.status(400).json({ message: 'Email already used' });
    }

    const user = await User.create({ name, email, password });

    // res.json — frontend ko JSON format mein response bhejte hain
    res.status(201).json({ message: 'Registered!', user });
  } catch (error) {
    res.status(500).json({ message: error.message });
  }
};

module.exports = { register };
08 — CRUD

CRUD Operations

Mongoose ke 4 main methods — har ek ka alag use case hai.

📋 find() — saray documents laao (array return) ▼
Returns: Array of objects — saray match karne wale documents.
Example
// Saray users laao
const users = await User.find();

// Condition ke saath — sirf doctors
const doctors = await User.find({ role: 'doctor' });

// Sirf kuch fields laao (.select)
const names = await User.find().select('name email -password');
🔍 findOne() — sirf ek document laao ▼
Returns: Single object ya null. Login ke liye email dhundna yahan hota hai.
Example
// Email se ek user dhundo
const user = await User.findOne({ email: 'ali@example.com' });

if (!user) {
  return res.status(404).json({ message: 'User not found' });
}
✏️ findOneAndUpdate() — dhundo aur update karo ▼
2 params: (1) kaunsi ID update karni, (2) kya update karna. ID req.params se, body req.body se.
Example
// :id params se aata hai (URL: /api/users/abc123)
// description body se aata hai (req.body)
const updated = await User.findOneAndUpdate(
  { _id: req.params.id },       // KAUNSA update karna — ID
  { description: req.body.description },  // KYA update karna
  { new: true }               // updated doc return karo
);
🗑️ findOneAndDelete() — dhundo aur delete karo ▼
Example
// Specific ID wala document delete karo
const deleted = await User.findOneAndDelete({ _id: req.params.id });

if (!deleted) {
  return res.status(404).json({ message: 'Not found' });
}
res.json({ message: 'Deleted!' });
09 — Dynamic Routes

:colon wala dynamic route

Route mein colon lagao to woh variable ban jaata hai — har request mein alag value ho sakti hai.

:id ka concept

Jis variable ko dynamic banana ho, us ke saath colon lagao: /:id

Ek route likho, hazaron alag IDs ke liye kaam kare. req.params.id se actual value milti hai.

Dynamic route example
// Route define karo
router.get('/:id', getUser);
router.delete('/:id', deleteUser);
router.patch('/:id/status', updateStatus);

// Controller mein value milti hai
const getUser = async (req, res) => {
  const id = req.params.id;   // URL: /api/users/abc123  → id = "abc123"
  const user = await User.findById(id);
  res.json(user);
};
Real example:
Request: GET /api/appointments/64a1b2c3d4e5f6
Controller: req.params.id = "64a1b2c3d4e5f6"
10 — Authentication

JWT Authentication

User login kare to ek token milta hai — har protected request mein woh token bhejta hai proof ke taur pe.

User Login
→
Password verify
→
JWT token generate
→
Cookie mein save
→
Protected route access
JWT token generate karna
const jwt = require('jsonwebtoken');

// Token banao — user ID andar pack karo
const token = jwt.sign(
  { id: user._id },          // payload — kya store karna
  process.env.JWT_SECRET,     // secret key — .env mein rakho
  { expiresIn: '7d' }        // 7 din baad expire
);

// Cookie mein bhejo — safe rehta hai
res.cookie('token', token, {
  httpOnly: true,  // JS se access nahi ho sakta (XSS se safe)
  maxAge: 7 * 24 * 60 * 60 * 1000,
});
Middleware — token verify karo
const protect = async (req, res, next) => {
  const token = req.cookies.token;
  
  if (!token) {
    return res.status(401).json({ message: 'Not authorized' });
  }

  const decoded = jwt.verify(token, process.env.JWT_SECRET);
  req.user = await User.findById(decoded.id).select('-password');
  
  next();  // sab theek — aage jaao
};
🛡️ Role-based Authorization

Authentication = "tum kaun ho?" | Authorization = "tum kya kar sakte ho?"

Role check middleware
const authorizeRole = (...roles) => {
  return (req, res, next) => {
    if (!roles.includes(req.user.role)) {
      return res.status(403).json({ message: 'Access denied!' });
    }
    next();
  };
};

// Route pe use karo
router.post('/', protect, authorizeRole('patient'), bookAppointment);
